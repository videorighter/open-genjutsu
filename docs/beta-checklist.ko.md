# 소규모 베타와 안정 릴리스

공개 HTTPS 스테이징과 실제 모델 평가가 완료되면 운영자가 3~5명에게 계정을 발급한다. API 키는 계정별로 연결하며 관리자 키가 자동 공유되지 않는다. 현재 자동 검증의 임시 사용자들은 베타 참여자가 아니다.

참여자는 로그인 → 템플릿 선택 → 영상·이미지 업로드 → 모델·프롬프트 편집 → 저장 후 새로고침 → 실행 계획 → 명시적인 비용 동의 → 결과 미리보기·다운로드를 진행한다. 모바일에서도 같은 흐름을 확인하고 실패 시 작업 ID, 발생 시간, 증상만 제출한다. 키·비밀번호·개인 미디어 URL은 피드백에 넣지 않는다. 실제 참여자 연락과 비용 추가 승인은 운영자가 진행한다.

관리자는 운영 현황에서 오래된 대기·확인 대기, 완료 시간, 남은 디스크를 확인한다. Worker 로그와 실제 무료 로컬 작업 결과를 함께 점검한다. 클라이언트 중복 클릭, 재접속, API/Worker 재시작은 유료 작업을 재제출하지 않아야 한다. `NEEDS_REVIEW`는 공급자 실행과 비용을 확인한 뒤 복구 또는 종료한다.

안정판 준비 조건은 핵심 제작 흐름의 차단 오류 해결, 실제 모델/청구 기록 확보, 공개 HTTPS 및 공급자 미디어 접근 확인, 같은 릴리스 계약으로 빈 볼륨 복원 성공, 별도 호스트의 암호화 백업 확보다. 실제 호스트 장애 복구 시간은 별도 호스트에서 측정한다. 같은 서버의 격리 복원 기록을 전체 운영 복구 시간으로 쓰지 않는다.

준비가 끝나면 새 `release/v<버전>` PR에서 package/lockfile과 CHANGELOG를 갱신하고 CI를 확인한다. GitHub `release` Environment 승인을 거친 RC를 스테이징에 digest로 배포하고, 안정판은 별도 버전과 승인으로 게시한다. 테스트가 끝나기 전에 RC 또는 안정판 게시 완료로 표시하지 않는다.
