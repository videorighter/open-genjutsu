# 직접 브라우저 검증 결과

> 이 문서는 초기 설계·편집기 검증 기록이다. 현재 서비스 구현과 운영 범위는 [운영 가이드](operations.ko.md)와 [서비스 검증](service-validation.ko.md)을 참고한다.


검증일: 2026-10-07 UTC. 개발 서버가 아닌 `npm run build` 결과를 `vite preview`로 실행해 검증했다. 브라우저 플러그인 도구가 제공되지 않아 Playwright로 실제 Chromium을 직접 조작했다.

최종 결과: **브라우저 테스트 36개(데스크톱 29·모바일 7), 단위 테스트 7개 모두 통과**. TypeScript 검사와 프로덕션 빌드도 통과했다. 브라우저 테스트는 재시도 없이 58초에 완료됐으며 실패·건너뛰기·flaky 결과는 0개였다.

## 환경과 범위

- Node.js 24.19.0, Chromium 151.0.7922.173, Playwright 1.63.0, axe-core Playwright 4.13.0.
- 데스크톱 기본 화면 1440×900. 가로 폭 1024·1280·1440·1920에서 가로 페이지 넘침을 검사했다.
- 모바일은 실제 Chromium의 Pixel 7 기기 에뮬레이션으로 터치 조작을 실행했다. 기본 화면 390×844, 가로 폭 320·360·390·430·740을 검사했다. 물리 Android 기기 검증은 아니다.
- 모든 시나리오에서 uncaught 오류와 console error를 수집해 0건을 확인했다. 초기 프로덕션 페이지에서 폰트 로딩을 기다린 후 실패한 요청 및 HTTP 400 이상 응답도 0건이었다.
- 최종 데스크톱·모바일 화면 캡처를 직접 시각적으로 확인했다.

## 발견한 문제와 수정

첫 32개 시나리오 실행에서 28개가 통과하고 4개가 실패했다. 실패 원인을 수정한 뒤 회귀 테스트와 추가 검증을 포함한 36개 전체 시나리오를 다시 실행했다.

1. **편집 직후 새로고침하면 마지막 변경 유실.** 기존 550ms 저장 지연이 끝나기 전 페이지가 닫히는 문제였다. 최신 워크플로를 유지하고 `beforeunload`, `pagehide`, 탭 숨김 시 저장을 즉시 완료하도록 수정했다. 지연을 기다리지 않고 편집→새로고침하는 회귀 테스트가 통과했다.
2. **도움말 창의 Delete가 배경 노드를 삭제.** 모달이 열린 동안 React Flow 삭제 단축키를 비활성화하고 배경을 `inert` 처리했다. 모달 포커스 제한과 복원도 재검증했다.
3. **작은 안내 문구의 색상 대비 부족.** 데스크톱·모바일 접근성 테스트가 실패한 원인으로, 브레드크럼·라이브러리 바닥글·노드 바닥글·프롬프트 보조 문구 등의 전경색을 조정했다.
4. **모바일에서 저장 실패 상태가 헤더 CSS에 가려짐.** 저장 실패 시 모바일에서도 보이는 알림을 추가했다. 저장소를 강제로 차단한 상태에서 알림과 JSON 내보내기를 검증했다.

## 접근성

axe의 WCAG 2 A/AA 및 2.1 A/AA 태그로 다음 상태를 검사했고 자동 검사 위반은 **0건**이었다.

- 데스크톱 기본 편집기, 입력·참조·분석·모션·출력 노드 설정, Custom API 설정.
- 도움말, 경고를 펼친 실행 계획, 새 워크플로 대화상자.
- 모바일 기본 편집기와 설정 패널.

이는 검사한 화면 상태에 대한 자동 검사 결과다. 전체 WCAG 준수 인증이나 스크린 리더를 사용하는 사람의 검증을 의미하지 않는다.

## 재실행

```bash
npm ci
npm test
npm run test:e2e
npm run test:e2e:report
```

시스템 `/usr/bin/chromium`을 자동 사용한다. 다른 브라우저 실행 파일은 `PLAYWRIGHT_CHROMIUM_EXECUTABLE`로 지정한다. 시스템 Chromium이 없는 환경에서는 `npx playwright install chromium`과 OS별 브라우저 의존 패키지 설치가 필요하다.

`playwright.config.ts`는 프로덕션 preview 서버를 자동 시작·종료한다. 테스트 구성은 `tests/e2e/`에 있다. HTML 보고서는 `playwright-report/`, JSON 결과와 실패 스크린샷·trace는 `test-results/`에 생성하며 Git에는 포함하지 않는다. 단위 테스트는 `vitest.config.ts`에서 브라우저 테스트와 분리했다.

## 아직 검증할 수 없는 부분

현재 저장소의 구현은 워크플로 편집기와 실행 계획 내보내기다. **Temporal 서버·Worker, 실제 OpenRouter/fal/Replicate/GPU 호출, 서버 미디어 업로드, 인증·API 키 보관은 연결되지 않았다.** 따라서 실제 영상 생성 품질, 과금, 작업 재시도·재시작 복구, 취소와 웹훅은 검증한 기능에 포함하지 않는다. 테스트 중 외부 생성 API를 호출하거나 API 키를 사용하지 않았다.

Firefox·Safari/WebKit과 물리 모바일 기기는 이번 환경에서 실행하지 않았다.
